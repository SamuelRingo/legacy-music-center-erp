### 1. CEK API — APAKAH SEMUA ENDPOINT DIGUNAKAN?

1. List SEMUA endpoint yang terdaftar di backend (routes/auth.js, routes/admin.js,
   routes/staff.js, routes/teacher.js, routes/student.js, routes/public.js).
2. Cek apakah setiap endpoint dipanggil di frontend (cari dengan grep atau
   telusuri semua file .jsx/.js di frontend/src).
3. Buat tabel:

| Endpoint | Dipanggil di Frontend? | File Pemanggil |
|---|---|---|
| GET /api/auth/me | ✅ | useAuth.js |

4. Untuk endpoint yang TIDAK digunakan:
   - Jika memang tidak dibutuhkan → catat sebagai "unused, bisa dihapus nanti".
   - Jika dibutuhkan tapi belum ada UI → catat sebagai "missing UI, perlu dibuat".

### 3. UI CONSISTENCY CHECK

1. Buka SETIAP halaman di aplikasi (dashboard, tabel, form, landing page).
2. Cek konsistensi:

   a. **Warna:**
      - Dashboard pages: white/gray background, blue accent.
      - Landing page: gold + dark (zinc-900/950).
      - Tidak boleh ada warna yang menyimpang dari palette.

   b. **Typography:**
      - Semua halaman pakai font Inter (atau font stack yang sama).
      - Ukuran heading konsisten: H1 (text-3xl), H2 (text-2xl), H3 (text-lg).
      - Body text: text-sm atau text-base.

   c. **Spacing:**
      - Container utama: p-6.
      - Gap antar card: gap-4 atau gap-6.
      - Margin antar section: mb-6 atau space-y-6.

   d. **Komponen:**
      - Semua tombol aksi di tabel pakai <ActionMenu> (hamburger).
      - Semua dialog konfirmasi pakai <ConfirmDialog>.
      - Semua tabel pakai <DataTable>.
      - Semua metric card pakai <MetricCard>.
      - Semua form pakai <Input>, <Textarea>, <Label> dari shadcn.

   e. **States:**
      - Loading: <LoadingSkeleton> (bukan <div>Loading...</div>).
      - Empty: <EmptyState> (bukan teks biasa).
      - Error: <ErrorState> dengan tombol "Coba Lagi".

3. Buat tabel checklist UI per halaman (seperti tabel audit sebelumnya).
4. Perbaiki inkonsistensi yang ditemukan.

### 4. PERFORMANCE CHECK

1. **Frontend:**
   - Jalankan `npm run build` di frontend. Apakah build sukses tanpa error/warning?

     besar (>500KB)? Kalau ya, rekomendasikan kompresi.

4. Buat laporan singkat dengan rekomendasi.

### 5. BASIC SECURITY CHECK

1. **Authentication:**
   - Cek SETIAP endpoint protected — apakah ada middleware `authenticate`?
   - Coba akses endpoint protected TANPA token → harus return 401.
   - Coba akses endpoint dengan token kadaluarsa → harus return 401.

2. **Authorization (RBAC):**
   - Cek SETIAP endpoint — apakah ada middleware `authorize` dengan role yang benar?
   - Coba akses endpoint Admin sebagai Staff → harus return 403.
   - Coba akses endpoint Teacher sebagai Student → harus return 403.

3. **API Key Exposure:**
   - Cek SELURUH frontend code — tidak boleh ada API key hardcode.
   - Cek SELURUH frontend code — tidak boleh ada Supabase key.
   - Cek SELURUH frontend code — tidak boleh ada Gemini key.
   - Semua key HARUS di backend (.env).

4. **Input Validation:**
   - Cek form register: apakah email divalidasi formatnya?
   - Cek form create user: apakah password minimal 6 karakter?
   - Cek form grading: apakah skor hanya 0-100?

5. **Password Security:**
   - Cek apakah password di-hash dengan bcrypt (bukan plain text).
   - Cek apakah endpoint change-password memverifikasi oldPassword.

6. Buat laporan keamanan dengan temuan dan rekomendasi.
